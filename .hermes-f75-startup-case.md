## Review status after the requested mapping change
- Speed+ (`0x0F`) and Speed- (`0x10`) call the same target/step/rerounding logic used by the Speed tile, including configured step, minimum device step, current target, requested speed, and metric/imperial rounding.
- Speed 4/8/12 (`0x2F`/`0x33`/`0x37`) call `changeSpeed(4.0/8.0/12.0)` respectively. Their alternate `key+0x41` checksums are accepted.
- Incline- (`0x0E`) calls the existing tile-style inclination decrement logic. Incline 4/8/12 (`0x15`/`0x19`/`0x1D`) call `changeInclination(4.0/8.0/12.0, same value)` respectively.
- Home (`0x0C`) emits a dedicated physical-home event; Return/Back (`0x02`) emits a dedicated physical-back event. Neither sends a treadmill command.
- The F75 parser owns the raw key mapping. `treadmill` exposes the generic hardware navigation signals, `homeform` forwards them as UI requests, and `main.qml` reuses the existing `navigateHome()`/`navigateBack(true)` navigation paths.
- Physical Home returns to the initial QZ page by popping nested pages; it does not stop an active workout. Physical Return performs one normal back navigation step, including page-specific `handleBack()` behavior.
- Existing Start/Stop/Emergency/Incline+ routing remains unchanged; speed/incline actions remain inside the F75 class.
- Verification: affected F75, `homeform`, `moc_treadmill`, and `moc_homeform` objects compiled successfully with `make -j1`; `qmllint --silent src/main.qml` returned 0; only pre-existing compiler warnings were emitted.
