# GPX and training program control

## A GPX route appears to change treadmill speed unexpectedly

### Provide first

- Confirm that the affected machine is a treadmill and give its exact model.
- State whether the goal is for the GPX route to control incline only, speed only, or both.
- Provide the current value of **Treadmill Speed Forcing**.
- Give one short controlled reproduction: start the treadmill from its console, set a fixed speed there, start the GPX in QZ, and do not press QZ speed controls.
- Report whether the speed changes by itself during that test.

### If still unclear

- Enable QZ Debug Log and repeat the same short test without touching QZ speed controls.
- Provide the debug log together with the approximate time of any unexpected speed change.
- If the behavior depends on a particular route, provide the GPX file used for the reproduction.
- Run a second short test with no GPX loaded if it is necessary to distinguish route behavior from machine or QZ manual-control behavior.

### Why it matters

- A controlled test with a fixed console speed separates commands generated by the route/program from manual speed commands issued through QZ.
- The Treadmill Speed Forcing value determines whether speed control is expected from the training path and should be checked before interpreting a log.
- A short log with no manual speed-button presses makes the source of a speed command much easier to identify.
- The GPX file is only needed after the basic control-path test shows that the behavior follows the route.
