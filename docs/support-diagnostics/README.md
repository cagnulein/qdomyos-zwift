# QZ Support Diagnostics

This directory contains reusable diagnostic intake guidance for QZ support. It focuses on the evidence to collect before choosing a solution, using a progressive approach: start with the smallest high-value set of information, then request deeper diagnostics only when needed.

## Categories

- [Connection and device discovery](connection-and-discovery.md)
- [Third-party app integration](third-party-apps.md)
- [Crashes and unexpected exits](crashes.md)
- [Heart rate source diagnostics](heart-rate.md)
- [Android installation and embedded consoles](android-installation.md)
- [External speed and cadence sensors](external-sensors.md)

## How to use these guides

Each entry is organized around a symptom and lists:

1. **Provide first** — the minimum information that usually separates the most likely causes.
2. **If still unclear** — additional settings, screenshots, or debug data to collect only when necessary.
3. **Why it matters** — what each item helps distinguish.

These guides complement the QZ FAQ. The FAQ documents known answers and solutions; support diagnostics documents what information is needed to determine which answer applies.

All examples must remain anonymous and should reflect current QZ behavior and documentation.
